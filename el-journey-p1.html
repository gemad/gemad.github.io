1- Why OS in Embedded?

As most of you already know The Super Loop this while one condition that holds all the code in the simple embedded systems so sequentially you measure, process and act at every cycle.[]

This kind of Firmware is convenient for sample systems, but once the system get more complex, you will definitely need some parallel execution method. by having multiple execution loops at the same time very complex, you will need something to manage the resource and keep the fairness distributions of them, you will need GUI , Filesystem, Network stack USB stack, ...

So you will need some sort of a schedule to switch between those loops — and you might implement this using timer, then the memory needed to store the not running tasks (Context) will increase so you need some sort of memory management. and as your application get complex you will need more components to manage the underneath operations, So you will find yourself implementing an OS and this OS will get more complex if your system hasa processor multi-cores.

So the role of the OS is :

  • Isolate the application (The added value part) from the system operation.

  • Make use of micro-processor/micro-controller capabilities.

  • Hardware abstraction and management.

  • Enable Multi-Tasking.

  • Make the system easy to program.

  • Make the system scalable.

  • Reduce time to market.

But most probably you wont be able to use normal OS on an embedded system because of ; limited resources and sometimes real time requirements, so you need an embedded OS.

This embedded OS could be Commercial or Free and real-time or not.

Examples of Commercial Embedded OSs:

  • GreenHill’s Integrity

  • QNX

  • WindRiver’s vxWorks.

  • …

Examples of free Embedded OSs:

  • FreeRTOS

  • Android

  • ziton

  • Linux

Embedded Linux is the usage of the Linux kernel and various open-source components in embedded systems

source

SpaceX uses Linux *on their primary flight computers for Dragon spacecraft and Falcon 9 launch vehicle, and also for their test vehicles, such as Grasshopper. Their version of Linux is based on the 3.2 kernel with real-time patches. SpaceX has also made their own mission-specific modifications to the kernel, and custom drivers have also been added. 3- What is the Embedded Linux Engineer job profiles ?

Embedded Linux Engineers need a lot of skill sets as this field is some how intersection between the embedded systems and the normal computing. There are many different job profiles for the embedded linux engineer we can split them into 3 main categories (The real world job could be an intersection of two or more of them)

1- BSP developer :

This job deals with (board support packages) like writing device drivers and low level hardware specific code. going into this field require you to know some low level stuff for example:

a) Linux kernel internals : how the kernel works and the framework for device drivers, and kernel processes management and mutual execution ..etc

b) basic OS fundamentals would be important here to make sense of all those kernel thing

c) Linux device drivers basics

d) computer architecture fundamentals would be essential; and it will be slightly different according to the ARCH of the target you working on (x86,ARM, MIPS, PowerPC and so on ) to write low level code in the drivers and Architecture Support Packages (ASP).

2- System integration :

this job deals with the Integration of all the components, boot-loader, kernel, third-party libraries and applications and in-house applications into a working system.and this field requires knowledge in the configuration and build process (of course basic knowledge from 1 and 3 is important to get the job done)there is many ways to get the embedded Linux system up and running) building the system from scratch : not common and take to much time and effort

b) using a pre-built ready OS from the vendor : not very customizable also not very common.

c) using a build system : this will automate the build processes after taking the configuration form you and there are many build systems available each for it’s goal but the most famous 2 are :

  • buildroot : simple and small but some times not very smart, used by Tesla and others.

  • YOCTO : much more common and more complex as well and have a steady learning curve.

diving here will also require a good knowledge in build systems such as make and cmake, version control systems mainly GIT and familiarity with topics such as kernel configurations,init scripts and systems and other topics.

3- Development of applications:

this job deals with the development of the application or the add value for your product. the application might be written in any programming language, but mainly in c/c++ and sometimes python.this field require knowledge in the Linux programming interfaces, like how to use the device drivers and the OS to write your application (File I/O, processes, threads, memory allocation, inter process communication methods,sockets,POSIX,etc)and of course might go higher to include different algorithms, data-structure or even machine learning according to the application you are aiming to achieve.

I recommend that you should have a basic Linux administration skills before diving into embedded Linux, this will make your embedded Linux journey much more smother and will give you a very good kick star. The beauty of Linux and embedded Linux is that, any knowledge you gain in either of them (the normal PC Linux or embedded) is applicable on the other.The must to know topics in administration are :

  • Intro to Linux

  • The shell (commonly bash) and it’s basic commands

  • The processes management

  • maybe some bash scripting

  • other topics like files system, Linux kernel and bootloaders

then after getting familiar with Linux and using it some time on your PC as the main OS (any distro), and try to do everything through the terminal you should know that there are like 3 main different jobs an embedded Linux engineer can work :

last but not least :- All those three jobs are intersected and you cannot define the bounders of each one- The journey of Linux and embedded Linux is not short, but very exciting and require a lot of skills and knowledge, you will always find tons of thing that you don’t know however hard you try, so keep on learning and don’t don’t hesitate to seek the support of the open source community.
